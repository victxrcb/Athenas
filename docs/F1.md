# F1 — andamento e validação

## Implementado

- PTY real via `portable-pty`, com leitura em canal limitado e eventos agrupados em ~16 ms.
- Scrollback em arquivo por sessão (limite de 5 MB), retomado ao abrir o terminal; busca local com Ctrl+F.
- Modal inicia Claude Code, Codex ou shell; a sidebar lista sessões. Ocultar a vista mantém o PTY vivo.
- UUID definido na abertura do Claude e `--resume <uuid>` na retomada. O Codex reabre com `codex resume` (seletor interativo, sem ID individual salvo).
- Colagem de imagem converte para PNG, salva localmente e insere o caminho no terminal.
- Terminal carrega sob demanda; estados confiáveis atuais: `rodando`, `concluído` e `erro`.

## Verificação em 11/11/2026

- `npm.cmd run build`: passou.
- `npm.cmd test`: passou, 2 testes da Home e validação de modo indisponível.
- `npm.cmd run e2e`: cenário de Home e modal passou no Microsoft Edge; o runner não encerrou sozinho e foi interrompido após o resultado.
- `cargo fmt --check`: passou.
- `cargo check --offline` / `cargo test --offline` / `npm.cmd run app`: bloqueados pelo Controle de Aplicativo do Windows ao executar um build script temporário do crate `icu_normalizer_data` (erro 4551). A execução nativa do PTY segue sem validação.
- `@xterm/addon-webgl` e `@xterm/addon-web-links` não estavam no cache npm e o acesso ao registry foi negado (`EACCES`). xterm, fit, search e unicode11 foram instalados do cache.
